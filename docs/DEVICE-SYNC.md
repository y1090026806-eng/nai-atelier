# 两台设备同步（电脑 ↔ 手机）

v1.9.0 起，NAI Atelier 自带「设备间同步」：电脑和手机各自离线生图、各自保存，连同一个 Wi-Fi 时点一下，就把两边的作品、画册、创作记录、回收站和提示词收藏合并成同一份。不需要网盘、不需要拷 `data/`，也不用再把项目压缩包传来传去。

> 前提：两台设备都升级到 **v1.9.0**（`data/config.json` 里的 `sync` 段就是新版本才会写的）。旧的 v1.8.0 没有同步服务，连不上。

## 1. 一次性设置

### 电脑端

1. 启动 `npm start`（或双击 `start-nai-atelier.bat`）。
2. 打开画廊头部右侧的**「同步」**按钮。
3. 勾选**「允许其他设备同步」**，端口保持 `3801`，点**「保存设置」**。
4. 对话框会显示类似 `在另一台设备填：192.168.10.36:3801`，以及一串同步口令 `nai-xxxx-xxxx-xxxx`。点口令旁的复制按钮。
5. 第一次开同步时 Windows 防火墙会弹窗，勾选**「专用网络」**并允许；如果当时点了取消，去「Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙」里给 Node.js 放行。

> 同步端口只在需要时开：不想同步时把开关关掉、保存即可。主应用本身仍然只监听 `127.0.0.1`，和以前一样。

### 手机端（Termux / PRoot Ubuntu 里跑同一份代码）

1. 把代码更新到 v1.9.0（见第 4 节），`npm install` 后照旧 `node server.js`。
2. 手机浏览器打开 `http://127.0.0.1:3800`，进「同步」面板。
3. 勾选「允许其他设备同步」，端口 `3801`，**口令填电脑上那串**（两边必须完全一致，区分大小写），保存。
4. 在「另一台设备」里填电脑的地址 `192.168.10.36:3801`，点**「开始同步」**。
5. 反过来让电脑主动连手机也可以：电脑端「另一台设备」填手机在局域网里的 IP + `3801`。

> 手机查自己的局域网 IP：Termux 里 `ifconfig wlan0` 或 `ip addr show wlan0`；更省事的办法是从手机发起同步，这样只需要知道电脑的 IP。电脑 IP 可以在同步面板里直接看到。

## 2. 日常怎么用

- 生图、改画册、删作品都照常，**完全离线**。
- 想合并时：任意一端打开「同步」→「开始同步」（会同时双向合并，不需要两边各点一次）。
- 第一次同步会把缺的图片都传一遍；之后只传新增/修改过的文件，没变化时几秒结束，面板会显示「新增/更新 X 项，删除 Y 项；接收/发送 Z 个文件」。
- 同步成功后画廊、画册、回收站、提示词库会自动刷新。

## 3. 合并规则（为什么不会互相覆盖）

| 情况 | 结果 |
| --- | --- |
| 两边都有、内容相同 | 保留一份，不重复下载 |
| 两边都有、都被改过 | 取修改时间较新的；时间完全相同则按内容哈希裁决，两端算出的结果一致 |
| 只在一边有 | 复制到另一边（图片一起传） |
| 一边彻底删除 | 墓碑记录时间更晚，另一边也删除对应文件 |
| 一边移入回收站 | 只是位置变化，另一边也进回收站，可随时恢复 |
| 两边都调过排序 | 以「最后一次拖动」的那端为基准，另一端的独有作品按创建时间插到对应位置 |
| API Key / 模型 / 提示词结构 | **不同步**，各端独立（`data/config.json` 里的密钥不会离开这台设备） |

每次同步前，服务端会把 `history/records/albums/trash/prompts` 五个索引备份到 `data/backups/<时间戳>/`，保留最近 5 份。真出问题时停掉服务，把备份里的 JSON 拷回 `data/` 即可回滚。

## 4. 代码怎么保持在两边同步

数据靠同步面板，代码靠 Git（仓库本来就有）：

```bash
# 两端都这样做，开始改代码之前
git pull

# 在某一端改完、跑过自检之后
npm run verify && npm run test:sync
git add -A && git commit -m "说明这次改了什么"
git push
```

要点：

- 两边都只提交代码和文档，`data/`、`outputs/` 已在 `.gitignore` 里，不会误传作品和 Key。
- 不要两端同时改同一段代码再合并——先 `pull` 再改，能省掉绝大多数冲突。
- 版本号只在 `package.json` / `server.js` 的 `APP_VERSION` / `index.html` 徽章 / `README.md` 顶部四处改，自检里的版本号现在从 `package.json` 读取，不用再手改。

## 5. 故障排查

| 现象 | 原因与处理 |
| --- | --- |
| 「同步口令不正确」 | 两边口令不一致。在两端「同步」面板里复制同一串口令（改过口令的话另一端也要重新填）。 |
| 「对方没有开同步」/ 连接被拒绝 | 对方的开关没开，或端口不一致，或服务没启动。 |
| 连接超时 | 两台设备不在同一个 Wi-Fi（比如手机走了流量、电脑连的是另一个频段/访客网络）。 |
| 电脑连不上手机 | 手机端同步服务绑在 `0.0.0.0:3801`，确认手机没有开启会拦入站连接的省电/防火墙类应用；优先用「手机连电脑」的方向。 |
| 端口被占用 | 同步面板里改一个端口（如 `3802`），两端同步改。 |
| 同步后结果不对 | 停服务，从 `data/backups/<最近时间戳>/` 拷回 JSON 再启动；把当时的提示发出来排查。 |

## 6. 安全边界

- 同步服务只暴露 `/sync/*` 四个接口，全部要求 `Authorization: Bearer <口令>`；主应用的 `/api/*` 不在这条监听上。
- 只用局域网，**不要**在路由器上给 3801 做端口转发，也不要把设备暴露到公网。
- 传输是明文 HTTP（仅在局域网内），口令和图片都可能被同网段抓包；在家用 Wi-Fi 下没问题，公共 Wi-Fi 下建议关掉同步开关。
